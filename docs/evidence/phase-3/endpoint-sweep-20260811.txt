Checkpoint 3.1, the endpoint sweep.

Run 2026-08-11 22:52 and 22:54 US Eastern, which is 2026-08-12 02:52 and 02:54 UTC,
from a scratch file-based app outside the repository, as 1.9 and phase P's probe
were. The file is named for the US Eastern date, which is the corpus convention for
a trading date; every timestamp inside it is UTC, which is what the provider's
counter is stamped in.

The token is never printed. Every URL and every error body passes through a redactor
before it reaches this file, and both passes were searched for the token and for its
percent-encoded form before committing. Neither appears.

Two passes. The first asks the seven questions the phase plan sets. The second
re-asks Q5 against names delisted INSIDE the five-year window, the first pass having
picked a name that delisted in 2003 and so proved nothing about delisted names in
general, and re-asks Q6's depth against a name whose distribution history is long.
Pass 2 also reads the allowance counter after the rollover the first pass fell
across.

The first pass opened against 90,518 units used on apiRequestsDate 2026-08-11 and
its first billable call came back against a counter reading 1. That is the daily
reset landing mid-sweep. It makes the first bracket in pass 1 print -90,517, which
is the bracket arithmetic being wrong across a day boundary rather than a
measurement, and it is the finding pass 0 was there to produce.
